Speech to text test

TOOLS-150. Pick a recording (about 5 minutes of two people talking), optionally paste the correct words, then run each way of turning speech into text. Nothing is uploaded to us. The browser's own speech service (Chrome, Edge) sends the audio to the browser maker's service; the other ways run on this computer after a one-time model download.

Open this page through a local web address, not by double-clicking the file. From a file the browser blocks the model engines (Moonshine, Whisper). In a terminal, in this folder, run python3 -m http.server 8765 and open http://localhost:8765/.

How the numbers are worked out

  • Delay is measured on the recording's own clock. Without the correct words we can only show when the first text appeared. With them, each correct word's spoken moment is estimated by spreading the words evenly over the stretches where someone is speaking (found from loudness). That is rough for a single word (about a second either way) but fair when comparing ways on the same file. The "typical delay" is the middle value of all correctly recognised words.
  • Word errors = (wrong + missing + extra words) / words in the correct text. Lower is better. Capital letters and punctuation are ignored.
  • Speed is how much audio the model handled per second of computer time. Under 1 means it cannot keep up live. Not available for the browser's own service.
  • The models are fed pieces cut at pauses (loudness based). The real tool would use a better pause detector, so treat results as slightly rough. The recording is sliced from memory, so this does not test the shared-tab-sound path (that is TOOLS-149), except for the browser's own service, which gets a real audio track.
  • CPU and graphics-chip load are not visible to a web page. Open the browser's Task Manager (Chrome: Shift+Esc) while a run is going and write down the CPU % of this tab and of the GPU process.
