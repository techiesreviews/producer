# TOOLS-150: live speech to text in the browser

Written 2026-11-09 by a research worker. Plan only; nothing here is built into the producer tool. Plain words first, details after.

## What is proven and what is not

- **Desk research:** done from the sources linked at the bottom. Every number says where it comes from. Anything I could not source is in the UNVERIFIED list (section e).
- **Test page:** built and run here in a real browser (Chrome 157, headless, Linux, AMD Ryzen 9 8945HS with a Radeon 780M graphics chip). It ran the model-inside-the-browser options on one 139-second clip. See "What I measured here" below. This is a smoke test on one computer, one speaker reading a book, one run each. It is not a benchmark and it is not Lex's computer.
- **Not tested at all:** the browser's own speech service (Web Speech API). Headless Chrome has no speech service, so that engine in the page is untried. It needs a normal Chrome or Edge on Lex's computer.
- **Still needs Lex's computer:** a real two-person recording, Web Speech, Dutch, Edge, and a Mac or Windows laptop. Steps are in section c.

## (a) Recommendation

Start with a small free model that runs inside the browser: **Moonshine** (English), in a background worker on the graphics chip when there is one (CPU otherwise), fed short pieces cut at pauses, with a rough "draft" shown every couple of seconds while someone is still talking. In my smoke test the draft text showed up about half a second after the words were spoken and the tiny download was 32 MB (CPU build) to 113 MB (graphics-chip build). Accuracy was a little below Whisper's. **Runner-up: Whisper base.en on the graphics chip**: in the same test it had the best accuracy (9.9 % word errors against 11.6 to 13.9 % for Moonshine) and a similar delay, but a larger download (294 MB at the browser's default precision) and it needs WebGPU; on a plain CPU it could not keep up live (0.8 to 0.9 times real time). **Dutch is the gap:** no small free model in the browser handles Dutch well enough today (Moonshine lists no Dutch; Whisper needs the small size or bigger, 249 MB, to reach a usable Dutch error rate, and that was not live-capable on CPU). For Dutch, plan on the browser's own speech service (free, Chrome and Edge only, audio goes to the browser maker) or a paid service later. The browser's own service also deserves a real test as a possible first choice: the standard now lets a page hand it an audio track instead of the microphone, which would take the shared-tab-plus-microphone mix. Whether stable Chrome and Edge honour that is UNVERIFIED and is the single most useful thing to test on Lex's computer.

Caution on the numbers: the gap between Moonshine and Whisper in my test (a few percentage points on 303 words) is inside what one run on one clip can show. The scorer also counts "Mr." against "mister" as a mistake, which hits every engine equally.

## What I measured here (smoke test, not a benchmark)

The graphics-chip runs needed Chrome's flag `--enable-unsafe-webgpu` here (headless Linux); normal Chrome on Windows or Mac does not. Settings: pause of 500 ms ends a piece, longest piece 12 s, a draft every 2 s. One run each. ## (c) What to measure on Lex's computer, exact steps

Please do this on the computer you stream from, in Chrome. If you can, repeat steps 4 to 8 in Edge too.

1. **Get the page open.** The page must come from a web address, not by double-clicking it (the browser blocks the model engines from a file). In a terminal: `cd /home/ubulex/Projects/producer/docs/wayfinder/producer/research/TOOLS-150-speech-test` then `python3 -m http.server 8765`. Open `http://localhost:8765/` in Chrome. (Or ask the fleet to serve that folder and give you the link.)
2. **The recording.** About 5 minutes of two people really talking (a past stream or call), saved as an audio or video file (mp3, wav, m4a, mp4 all fine). Use the same file for every run. Dutch: do the Dutch runs with a Dutch recording.
3. **The correct words.** Paste the true text of that recording into box 2, with numbers written as spoken ("five"). If 5 minutes is too much typing, set "Only play the first ... seconds" to 120 and correct only those words. Without this text you get speed numbers but no accuracy or delay numbers.
4. In box 1 click **Choose file** and pick the recording. Leave "Hear it through the speakers" off. Language: English (Dutch later).
5. **Run 1: browser service.** Way = Web Speech API. Leave "recognise on this computer" off. Click **Start**. It plays in real time, so wait for "Done". If it says nothing for 20 seconds, the browser is probably listening to the microphone instead of the audio track: write that down, it is an important result.
6. **Run 2: browser service on this computer** (Chrome only). Tick "Ask the browser to recognise on this computer", Start. The first time it may download a language pack.
7. **Run 3: Moonshine tiny.** Way = Moonshine tiny, Runs on = CPU, Start. While it runs press **Shift+Esc** in Chrome (Task Manager) and write down the CPU % of this tab. Repeat with Runs on = Graphics chip, and write down the CPU % of this tab and of the "GPU Process".
8. **Run 4: Moonshine base** on Graphics chip. **Run 5: Whisper base.en** on Graphics chip. **Run 6 (Dutch recording only): Whisper small**, language Dutch, Graphics chip. Optional: Whisper tiny.en on CPU.
9. Click **Copy results as text** and paste it into the TOOLS-150 card thread together with: the computer (model, memory), the browser name and version, and the CPU % you wrote down.

What to compare: "first text after speech starts", the middle and slowest-1-in-10 delay, "Speed" (anything under 1x cannot work live), word errors, download size, and whether Web Speech took the audio track. TOOLS-154 turns these into the delay target; this card only hands over the numbers.

## (d) Ideas to improve accuracy and delay later (Prompter can reuse them)

- **Better pause detection.** The page cuts pieces on loudness. A real voice detector in the browser (for example the ISC-licensed `@ricky0123/vad-web`, which Moonshine's own browser library forks) will cut at real sentence ends and ignore noise and music.
- **Commit only stable words.** Show a draft every second or two, but only lock in words that appeared the same in two drafts in a row, and keep the last few seconds of audio as context. This is the known approach for turning Whisper into a live system (method name "local agreement"; I did not open the paper this session).
- **Teach it the names.** The producer knows the guest's name, the company and the question list. Whisper models accept a text prompt with such words; Deepgram has "keyterm" boosting (its Nova-3 post mentions it). The browser's own speech service cannot be biased (grammars were removed from the Web Speech API, MDN).
- **One stream per person.** Host from the microphone, guest from the shared tab, each recognised separately. That labels who spoke for free, avoids two voices overlapping in one stream, and the host should wear headphones so the microphone does not re-record the guest. Cost: twice the compute (or twice the paid minutes).
- **Do the audio work in a background worker.** Capture, convert to 16 kHz mono and detect pauses in an audio worklet, inference in a worker, so the screen never freezes. The test page already runs the model in a worker.
- **Download once.** Ask the browser to keep the model files (persistent storage) and pre-load them when the page opens, so the first live minute does not pay a 30 second load plus warm-up.
- **Use the graphics chip when it is there, precision matters.** Smaller precision files (q8 or q4) cut the download a lot; the page has a Precision menu to compare. Test fp16 encoder with a q4 decoder for Whisper.
- **Wait for streaming Moonshine in the browser.** The v2 design keeps state between chunks, so it does not re-read old audio and the delay does not grow. Re-check when an official WASM or WebGPU build appears.
- **Prompter reuse.** `src/follow.mjs` only needs lists of heard words (`speechWords`) and already tolerates cut-off draft words (`sameWord`), so any engine can feed it. `src/speech.mjs` (`speechKeeper`) is shaped around Web Speech events and its restart watchdog; a local engine would need a small adapter that emits the same `onResult` shape and keeps the reconnect hint quiet. A shared "engine" interface (start, stop, onWords with draft/final flag) would let the Prompter and the producer share one engine. Prompter matching is order-based against a known script, so it needs less accuracy than the producer, which must understand free talk.
- **Fix formats before scoring and matching.** Normalise numbers, "Mr." and "Dr." the way the Prompter's `speechWords` already strips URLs and labels.

- Any published accuracy or delay figure for the Web Speech API (cloud or on-device) in Chrome or Edge.
- Whether stable Chrome and stable Edge actually use the `MediaStreamTrack` passed to `start()`. MDN documents the argument; Edge's docs show it only for the on-device model in Canary/Dev 150; I found no stable-browser confirmation. Safari and Firefox: not found.
- Which languages Chrome's on-device speech supports, and whether Dutch is one.
- The exact Chrome version that shipped on-device speech (intent thread says 135 planned; a developer post says 139).
- Edge stable behaviour: caniuse notes Edge fires no events in some versions, while the Prompter README says Edge works with occasional drops.
- Moonshine v2 in a browser as true streaming: no official browser build found; the only browser export (community, Workmind) is one-shot, q8 files 71 + 87 MB.
- Moonshine v2 Dutch (not listed for speech to text). Moonshine's 50 / 148 / 258 ms latency is native code on an Apple M3, not a browser.
- Moonshine v1 against Whisper accuracy tables from the paper (only the abstract and a model-card mean were read).
- Whisper averages on the Open ASR leaderboard (not fetched).
- Delay and load for any engine on a laptop other than the one I used; CPU and GPU percent for all (needs Task Manager).
- sherpa-onnx browser model sizes, whether it takes a MediaStream, and whether any Dutch streaming model exists (the release list I scanned had none; not exhaustive).
- Parakeet v3 and Voxtral Realtime in a browser (size, speed). Voxtral's 16 GB GPU need is from its card.
- Vosk: delay, CPU, and a Dutch model in tar.gz form for vosk-browser (the demo list has none).
- Deepgram: whether the multilingual model covers Dutch (the docs page was unclear), and its latency in milliseconds. AssemblyAI: streaming languages and latency. Both vendors' accuracy claims are their own.
- Whether mixing shared-tab sound with the microphone lowers accuracy (TOOLS-149 covers the mix; this page slices a file from memory, except Web Speech which gets a real track).
- Whether a loudness pause detector is good enough on two overlapping voices.
